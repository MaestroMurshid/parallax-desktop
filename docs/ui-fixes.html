UI audit · proposed changes

Contrast and target fixes

Four changes, shown against the app’s real palette and real content. The style the design is reaching for — Swiss minimalism — lists high contrast among its defining traits. The implementation has the minimalism and inverts the contrast.

01

Lift the chrome text

--meta and --edge-label are the same value and carry nearly all secondary text. On the void that scrapes AA at 4.50. Inside panels — where almost all of it actually lives — it drops to 3.94 and fails.

One token, two characters different. It stays firmly in the quiet register — this is not a brightening of the app, it is the difference between readable and not.

02

Give the small controls a body

Nineteen pointer targets have padding: 0, so the clickable area is exactly the text — about 12×14px. WCAG 2.2 AA asks for 24×24. The fix is padding plus a negative margin, so nothing moves visually and only the hit area grows. Dashed outline shows the real target.

03

Raise the type floor

29 declarations sit below 12px, bottoming out at 6.5px in the legend glosses. The legend is the one thing that teaches the canvas’s vocabulary, so it is the worst place to save space. A floor of 11px costs almost nothing here.

04

A second route to connect

The stub handle is hover-only, which is the guidance’s named High-severity anti-pattern — and it means touch and keyboard have no path at all. The handle stays; it just stops being the only door. The analysis block already holds proposed connections, so manual linking belongs beside them.
